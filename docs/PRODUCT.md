# Product

Delta Qoralis is planned as a human-controlled system that takes a potential business from discovery through service delivery:

Business discovery → Website analysis → Lead qualification → Contact discovery → Outreach draft → Human approval → Email → Replies → Client requirements → Website generation → Preview → Payment → Deployment → Support subscription.

The foundation is complete and Phase 1 — Lead Discovery is complete. Phase 2 — Website Crawling is completed. Phase 3 — Website Analysis is current and is not implemented. The implementation defines a provider-independent discovery contract and a persistence boundary for audited, idempotent creation of normalized discovery candidates. It supports explicit, disabled-by-default Geoapify configuration and a bounded adapter for four exact business categories. `runBoundedDiscovery` orchestrates bounded pages for one injected provider and persists accepted outcomes. `npm run discover` is the controlled operator command that composes those pieces for one explicit human actor. Discovery is operational through that command. One safe page fetch also exists: every connection goes through DQ-006, the socket is pinned, and redirects are revalidated. One present lead website can become in-memory crawl evidence. One already-built attempt can be stored as append-only evidence and read back by id. Stored HTML is untrusted data. A failed attempt stores an allowlisted code and no raw error message. DQ-023 — Bounded Single-Page Crawl Run is completed. One run selects at most 60 eligible snapshots, crawls them one at a time, persists each finished attempt immediately, and returns numeric counts. There is no spider, no analysis, and no outreach. DQ-020, DQ-021, DQ-022 — Persisted Single-Page Crawl Evidence, and DQ-023 — Bounded Single-Page Crawl Run are completed. DQ-024 — D1 Crawl Store and Async Run Core is completed. `DQ-025 — GitHub Actions Scheduled Crawl Runner and D1 Worker Gateway` is completed. Production activation was verified through GitHub Actions run 39773510876. The Node runner fetches the public website through the DQ-020 pinned transport, and the Worker only selects and persists production D1 evidence. Discovery still uses local SQLite and does not feed production D1 automatically. DQ-030–039 remain planned. The next development action is to architect the first Phase 3 website-analysis slice before implementation. Lead qualification, contact discovery, messaging, payments, deployment, and a dashboard are not implemented.
